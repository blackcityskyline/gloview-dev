# REFACTORING — контекст между сессиями

> Этот файл — рабочая память рефакторинга gloview. Обновляется после каждого шага:
> отмечаем чекбоксы, дописываем «Результаты» и «Лог сессий». Новая сессия начинает с чтения этого файла.

## Как собрать и проверить

```bash
cmake --build build -j$(nproc)   # цель: build/gloview.so, Hyprland 0.56.2, lua 5.5.1, GLES 3.2
```

Критерий готовности шага: **сборка зелёная** + поведение не изменилось (если шаг не багфикс).
Плагин грузится в живой Hyprland через hyprpm — ручная проверка визуала вне CI невозможна,
поэтому каждый шаг должен быть минимальным и механически эквивалентным.

### Костыли: оправданные (НЕ трогать)

- Хуки `shouldRenderWindow`/`damageSurface` по substring-сигнатуре — альтернативы в plugin API нет.
  Улучшение: громкий failure при промахе (сейчас damageSurface молча деградирует).
- Собственный blur-пайплайн (`blur.*`) — глобальный `decoration:blur:*` плагину не переопределить.
- Software-cursor fallback — нужен из-за порядка проходов, но см. план R6.

### Костыли самопорождённые (цели для устранения)

1. `cursor.cpp/hpp` (~210 строк) существует только потому, что оверлей рисуется в `RENDER_LAST_MOMENT`
   (после курсора Hyprland). Баг: первый ход `moveDamage` возвращает monitor-local, остальные global
   (cursor.cpp:42–46 vs :50–59), замаскирован full-damage при hover.
2. Свой клон трекера фокуса (`m_focusHistory`) вместо отказа от `fullWindowFocus()` на hover.
3. Отложенный клик 400мс ради doubleclick-mode: 4 члена состояния + cancelPendingClick() в 4 местах.
4. Back-dating хаки анимаций: `close()` двигает `m_animStart`, `replayReflow()` откатывает на полную длительность.
