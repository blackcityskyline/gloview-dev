# REFACTORING — контекст между сессиями

> Этот файл — рабочая память рефакторинга gloview. Обновляется после каждого шага:
> отмечаем чекбоксы, дописываем «Результаты» и «Лог сессий». Новая сессия начинает с чтения этого файла.

## Как собрать и проверить

```bash
cmake --build build -j$(nproc)   # цель: build/gloview.so, Hyprland 0.56.2, lua 5.5.1, GLES 3.2
```

Критерий готовности шага: **сборка зелёная** + поведение не изменилось (если шаг не багфикс).
Плагин грузится в живой Hyprland через hyprpm — ручная проверка визуала вне CI невозможна,
поэтому каждый шаг должен быть минимальным и механически эквивалентным.

### Костыли: оправданные (НЕ трогать)

- Хуки `shouldRenderWindow`/`damageSurface` по substring-сигнатуре — альтернативы в plugin API нет.
  Улучшение: громкий failure при промахе (сейчас damageSurface молча деградирует).
- Собственный blur-пайплайн (`blur.*`) — глобальный `decoration:blur:*` плагину не переопределить.
- Software-cursor fallback — нужен из-за порядка проходов, но см. план R6.

### Костыли самопорождённые (цели для устранения)

1. `cursor.cpp/hpp` (~210 строк) существует только потому, что оверлей рисуется в `RENDER_LAST_MOMENT`
   (после курсора Hyprland). Баг: первый ход `moveDamage` возвращает monitor-local, остальные global
   (cursor.cpp:42–46 vs :50–59), замаскирован full-damage при hover.
2. Свой клон трекера фокуса (`m_focusHistory`) вместо отказа от `fullWindowFocus()` на hover.
3. Отложенный клик 400мс ради doubleclick-mode: 4 члена состояния + cancelPendingClick() в 4 местах.
4. Back-dating хаки анимаций: `close()` двигает `m_animStart`, `replayReflow()` откатывает на полную длительность.

### Диагностика стыка (сессия 4)

Тест с duration=1500 показал: чёрная вспышка НЕ растягивается (событие, не
кривая), разрыв блюра растягивается. Вывод: границу нельзя закрыть кривыми
бэкдропа — окна исчезали/появлялись одним кадром. Решение S7: фейд самих окон.
Остаточный артефакт из заметки ниже более не актуален: blur-behind теперь
плавно принадлежит окнам весь переход.

### Остаточные артефакты

- (устранено S7) микро-скачок blur-behind на handoff — окна теперь сами
  несут свой блюр через весь переход.
- Сессия 3-эры «шлейфы» и «чёрное мигание» не воспроизводятся после S7
  (проверить на duration=360).

### Матрица визуальной проверки (рендер×блюр)

| Сценарий | Что должно быть |
|---|---|
| Открытие, стол с окнами | окна не мигают: блюр Hyprland «растворяется» в плагинном по кривой duration |
| Открытие, пустой стол | резкий вельюпейпер → блюр по кривой, без щелчка |
| Закрытие | плитки доезжают → блюр тает над голым вельюпейпером (БЕЗ призраков окон), окна появляются один раз при посадке |
| Toggle-spam mid-анимации | прогресс непрерывный, без прыжков |
| Смена воркспейса карточкой (mid-session) | бэкдроп НЕ переблюривается между двумя обычными ws (~20% скачок яркости = регресс); chrome не переигрывает открытие |
| fullscreen_background=1 + mpv | вход на ws с mpv → блюр живой за видео (каждый кадр); уход с ws → один перерасчёт на вельюпейпер |
| Конфиг live: passes/size/resolution/strength/backdrop_color | применяется сразу, без закрытия оверлея |
| blur=0 / выключен | только dim-рект по кривой, как раньше |

**Итог Фазы 1:** 7233 → 7119 строк (−114), при этом добавлены `overlay_gl.hpp`,
`BlurCache`, `Tween`, 6 хелпер-методов и `LRect::contains()`; исправлен реальный
баг blur-инвалидации. Поведение не менялось (кроме починенного бага).
Важно для будущих сессий: в R5 close() семантически тонкое место — при закрытии
`m_progress = 1 - timeline.raw()`, поэтому resume это `seek(1.0 - m_progress)`.

**F1 (кроссфейд) — контракт:** `open()` → `m_entryPrime` → один «priming» кадр с
видимыми окнами → `renderBackdrop` захватывает currentFB в `m_openSnapFB` →
блюр+dim блитятся поверх замороженного кадра с альфой `k=eased()`. На выходе —
обратно к снапшоту, реального окна подмены не видно. Кэш блюра теперь несёт
ПОЛНЫЙ dim/силу (анимация только альфой блита). Визуальная проверка в живом
Hyprland обязательна: вход/выход на столе с окнами, на пустом, mpv fullscreen,
быстрый toggle-spam.
