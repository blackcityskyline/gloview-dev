# feat/stash-secret — окна вне воркспейса

Цель: показывать окна, которых нет ни на одном видимом воркспейсе — из **stash** и из
**secret workspaces** — отдельной полосой миниатюр, и прятать их в карточку воркспейса,
если он в фокусе.

## Задумано (не реализовано)

**Полоса под картой.** Миниатюры очень мелкие, помещаются в промежуток между превью на
гриде и бендом полосы. При наведении миниатюра растёт и слегка уменьшает окно на гриде,
чтобы не перекрывать её.

**Внутри карточки.** Если сфокусирован воркспейс, на котором есть такие окна, они
показываются вертикальной линией **справа** от окна (при горизонтальном стрипе), мелкие
миниатюры единого размера, вписанные в вертикальное пространство — по аналогии с каруселью.

## Профетч: что удалось проверить

Проверено на этой машине, Hyprland **0.56.2** (`efb50993780079460b0cbed1363e2166a2de1d9f`):

| что | результат |
|---|---|
| secret workspaces в 0.56.2 | **нет.** `nm -DC /usr/bin/Hyprland \| grep -ci secret` → 0; `strings … \| grep -i secret` → 0; в `/usr/include/hyprland/` нет ни `secretWorkspace`, ни `setSecretWorkspace` |
| плагин `stash` в hyprland-plugins | **нет.** В репозитории только `borders-plus-plus`, `csgo-vulkan-fix`, `hyprbars`, `hyprfocus` |
| `hyprwm/hyprland-stash` | 404, такого репозитория нет |
| special workspaces (`special:`) | есть, это и есть скретчпад; сейчас его показывает `show_special`. Это **не** secret workspaces |

## Блокеры — нужно от пользователя

1. **Откуда stash?** Ни в hyprland-plugins, ни отдельного репозитория hyprwm. Либо это
   сторонний плагин, либо новая фича в ещё не вышедшем Hyprland, либо имеется в виду
   hyprview. Без источника нельзя понять, как доставать список окон: у stash-плагина
   свой API и свои структуры, а не Hyprland'овский `windowState()`.
2. **Какая версия Hyprland нужна для secret workspaces?** На 0.56.2 писать нечего —
   нет ни заголовков, ни символов. Если целевая версия новее, код придётся писать
   вперёд, проверяя наличие по `findFunctionsByName`, и он не будет проверен на той
   машине, где сейчас ведётся разработка. Это ровно тот режим, в котором сегодня уже
   потеряны сутки на гипотезах.

## Чего делать нельзя

- Додумывать API. Сутки вчера ушли на пять версий без красного цикла; начинать фичу с
  выдуманного интерфейса — значит повторить.
- Трогать код до ответа на оба вопроса: иначе первая же сборка будет вслепую.

## Смежное: баг с превью на стрипе

Отдельная задача, тянется с прошлой сессии: у плавающего окна ~300×300 в центре экрана
в карточке полосы вместо окна видна заливка цвета карточки. Кода, который специально
исключал бы плавающие окна, не найдено: `buildStrip` кладёт в карточку все окна
воркспейса, слот считается как `rel = позиция/размер, нормированные на монитор`, для
300×300 на 3840×2160 это ≈15×11 логических пикселей. Гипотеза «окно рисуется, но
крошечное» не проверена. В коде есть диагностика `renderStrip BAD slot` — включается
`debug_logs = 1`.
