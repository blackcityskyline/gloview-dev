# CANDIDATES — «чёрный блинк» при входе (2 кадра @60fps)

Симптом: в момент bind-триггера 1-3 кадра: терминал отрисован чётко и живьём,
ВСЁ остальное — чёрное (не background_color — проверено красным). Оверлей в этих
кадрах не виден (k≈0 и не должен). Длительность не зависит от duration.
После pump-фиксов сократился с ~30 кадров до 2-3.

## Опровергнутое (не возвращаться)

| Гипотеза | Опровергнуто |
|---|---|
| Наш бэкдроп/blur-слой | blur=0 → блинк остался |
| fullscreen_background/mpv путь | =0 → остался |
| Обои (noctalia/swaybg/отсутствие) | все три сценария → одинаково |
| Клир background_color | runtime=red → кадры чёрные (красный замечен ровно один раз — сразу после eval, до reloadConfig плагина, который восстанавливает файловое значение rgb(000000)) |
| Фейд реальных окон (winFade) | удалён (S12) — блинк был до и после |
| Курсор/динамические курсоры | выключены пользователем |

## Кандидаты (по убыванию вероятности)

### C1. Кадр с неполным incoming damage → фон выкинут simplify'ом
`Pass::render()`: `m_damage = damage_.copy()` — снимок на старте кадра. Если в
момент триггера снимок содержал только каретку терминала (а наш full-monitor
damage из input-контекста опоздал/был съеден), то `simplify()` в обратном
проходе дискардит все элементы вне региона — включая фон; окна рисуются
(каретка в их регионе); буфер свежий → нули вокруг.
**Фальсификация:** `debug:pass=1` форсит бесконечный damage (`m_damage =
INT32_MAX box`) → блинк должен ИСЧЕЗНУТЬ. Плюс debug рисует occluded-регионы
на экране — в slowmo-видео будут видны цветные боксы на месте выброшенного.

### C2. Opaque-subtraction от превью/окон выкидывает bg-layer
`simplify()` идёт в обратном порядке и вычитает `opaqueRegion()` каждого
элемента. Наши COverlayPass имеют disableSimplification, но превью — это
ЧУЖИЕ CSurfacePassElement без такого флага: для непрозрачного окна
opaqueRegion = весь его бокс → вычитается из newDamage → если bg-layer bbox
перестаёт пересекаться → discard. При e≈0 оверлею нечего показывать поверх —
кадр выглядит «всё чёрное кроме окон».
**Фальсификация:** тот же debug:pass (инфинити-damage обнуляет вычитание);
дополнительно в slowmo смотреть debug-боксы.

### C3. renderBackground уходит в CLEAR-only
`m_backgroundOpacity->isBeingAnimated()` или `getBackground()`→null (async
reload ассета, `doLater(reset)`) → очередь получает только CClear. Но красный
тест говорит: клир до экрана не доходит в флешевые кадры → этот кандидат
может объяснять ТОЛЬКО вариант с красной вспышкой (наблюдался 1 раз).
**Фальсификация:** toggle `misc:disable_hyprland_logo` 0↔1.

### C4. Стрей scheduleFrame/pendingFrame-коммит без damage
Вариант C1 на уровне планирования: чужой/наш scheduleFrame без парного damage.
**Фальсификация:** сборка без pump (только Front-phase re-arm) → сравнить
число флешевых кадров.

### C5. GL-state утечка из frosted backing (scissor/blend) в следующий кадр
**Фальсификация:** сборка с отключённым backing (один if) → блинк?

### C6. m_blurFBDirty poke в open() → CPreBlur семплит пустой FB → чёрный
m_blurFB подложка тайлов/стрипа. Не объясняет фуллскрин, но может давать
тёмные пятна в то же время.
**Фальсификация:** закомментировать poke на одну сборку.

## Решающий эксперимент (делать первым)

`debug:pass=1` + toggle + видео. Три исхода:
1. **Блинк исчез** → семейство C1/C2 подтверждено; дальше по debug-боксам на
   видео определяем, кто именно вычитал фон (C1 vs C2).
2. **Блинк остался тем же** → damage ни при чём; фокус на C5/C6 и на том,
   кто вообще коммитит эти кадры (смотреть YAVG-профиль + наши stage-логи).
3. **Блинк изменился (стал цветным/другой длительности)** → частичное
   подтверждение C1; продолжаем с видео.
